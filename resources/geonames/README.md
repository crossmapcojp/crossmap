# Church geonames

`japan.json` is the compact Japanese search-location catalog used at query time.

`japanese-local-goverment-offices.json` stores representative government-office points keyed by the same administrative codes. The 47 prefectural offices were resolved through OpenStreetMap Nominatim on 2026-07-18; 1,912 municipality/ward offices come from MLIT's P34 municipal-office data (2014-08-31), and six newer entities remain explicitly tagged `GEONAME_FALLBACK` for later review. `GeoCatalogBuilder` copies only the center point into `japan.json`. These points disambiguate same-name entities and label device-assisted results; they are not boundaries and this file intentionally contains no search radius.

`church-ja-all.json` is generated by `./gradlew :crawl:prepareChurchGeoNames`. It is the unique union of Japanese geonames detected in Google Maps church titles and Japanese addresses. Each entry records available `en`, `ko`, `pt`, and `id` translations plus whether it was observed in a title, address, or both. `church-usage.json` records each church's `googlePlaceTitle` beside its deduplicated `title` and `address` geonames, making it possible to review which exact title text produced the detected title geonames. Snapshot creation uses those terms only for the correct church document.

`jma-city.json` is downloaded once from the [Japan Meteorological Agency multilingual city dictionary](https://www.data.jma.go.jp/multi/data/dictionary/city.json). `GeoName` validates it, maps JMA's `english`, `korean`, `portuguese`, and `indonesian` fields to Crossmap language codes, and creates both full municipality and suffix-free aliases. JMA values are merged with GeoNames alternate names before the church review queues are generated.

The eight `church-ja-{en,ko,pt,id}-{title,address}-missing.csv` files are committed review queues. Title geonames are separated so they can be reviewed first; the address queues contain address-only names, and a name used in both appears only in the title queue. Fill the blank second column with a reviewed translation and rerun the task; nonblank human values are preserved and merged with official GeoNames translations. Different Japanese aliases may legitimately share a translated spelling, but each per-church language index deduplicates the resulting search terms and omits any name that has no translation in that index language.

`geoname-duplicated-church-name.csv` is the reviewed exclusion list for church or religious-place names that GeoNames also exposes as place aliases. `JapaneseGeoNameCleaner` applies this file before any church-name decomposition, address matching, translation queue, or index input. It also rejects katakana-only aliases such as `マリ` and address-block labels such as `一丁目`; mixed-script official places such as `ユーカリが丘` remain valid. Add one Japanese name per row when another high-confidence collision is found.

Large official inputs remain ignored under `cache/geoname`:

- `japan/JP.txt` comes from `https://download.geonames.org/export/dump/JP.zip`.
- `japan/alternatenames/JP.txt` comes from `https://download.geonames.org/export/dump/alternatenames/JP.zip` and is joined to `JP.txt` by `geonameid`.

Each `church-geonames` run also creates `logs/YYYY-MM-DD-HH-mm-geoname-translation-coverage.log`, which records cleanup counts, translated/missing counts before and after adding JMA data, and the exact missing-count reduction per language. `prepare-geoname-cache` separately logs raw-alias totals and removal counts for reviewed church names, katakana-only aliases, and `丁目` blocks.
